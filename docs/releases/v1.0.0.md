## Preflight validation

Run these from a clean clone of the target commit. All commands below were
re-run successfully against the target commit as part of preparing this
document.

```sh
# Configure, build, and test the library itself.
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=c++
cmake --build build --config Release --parallel 2
ctest --test-dir build -C Release --output-on-failure

# Install to a temporary prefix.
cmake --install build --config Release --prefix /tmp/logrange-v1.0.0-prefix

# Build and run the installed-package quickstart as an external
# find_package(LogRange CONFIG REQUIRED) consumer.
cmake -S examples/quickstart -B quickstart-build \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=/tmp/logrange-v1.0.0-prefix
cmake --build quickstart-build --config Release --parallel 2
ctest --test-dir quickstart-build -C Release --output-on-failure
```

Expected result: 4/4 tests pass in the main build (`log_math`, `rp_accum`,
`pos_accum`, `accuracy`), install succeeds, and the quickstart consumer
configures against the installed package config, builds, and passes its
test.

## Maintainer-only checklist: creating the tag and GitHub Release

This section is **not** performed by this PR. It is the explicit,
maintainer-authorized sequence for whenever publication is decided:

1. Confirm `main`'s tip is the intended target commit (re-run the preflight
   above if `main` advanced since this document was written) and that its CI
   run is green for all three jobs.
2. Create an annotated tag on that commit:
   ```sh
   git tag -a v1.0.0 <target-commit-sha> -m "LogRange runtime v1.0.0"
   git push origin v1.0.0
   ```
3. Create a GitHub Release from the `v1.0.0` tag, using the draft release
   notes below (edit only if the target commit or CI run changed).
4. Do not mark the release as a pre-release; this is intended as the first
   stable release.
5. Do not attach compiled binaries — this is a header-only library; the
   source archive that GitHub attaches automatically is sufficient.

## Rollback / correction guidance

Once a tag is public, treat it as immutable:

- **Do not** delete or re-point (force-move) the `v1.0.0` tag, even if a
  defect is found shortly after publication. Rewriting a public tag breaks
  any consumer that has already resolved it (e.g. via a package manager
  lockfile or a pinned `FetchContent`/`git submodule` reference).
- **Do not** delete the corresponding GitHub Release once other users may
  have seen or depended on it.
- If a defect is discovered after publication, **publish a corrective patch
  release** (`v1.0.1`) with a fix and release notes describing the
  correction, following the same maintainer-only checklist above.
- If the defect is severe enough that `v1.0.0` must not be used, mark the
  `v1.0.0` GitHub Release as a "pre-release" or add a prominent note in its
  description pointing to the corrective release, rather than removing it.

### LogRange runtime `v1.0.0`

First standalone, supported release of the header-only C++17 LogRange
runtime: a small library for accumulating sums of terms that would underflow
or overflow in ordinary linear `double` arithmetic, by representing values
as `{sign, log|x|}` and combining them in the log domain.

**Public API**

- `logrange::log_value` — the `{sign, log|x|}` representation, with the
  arithmetic helpers (`logsumexp2`, `log_add`, `log_mul`, `log_div`) used to
  combine it.
- `logrange::pos_accum` — the faster accumulator for reductions where every
  term is known to be non-negative.
- `logrange::rp_accum` — the general accumulator for reductions where terms
  can have either sign or can cancel, at additional cost.

See the [API guide](../api.md) and [guarantees](../guarantees.md) for the
full operation list, error contract, and scope.

**Packaging**

- Header-only; no dependencies beyond the C++ standard library.
- CMake install/export support: `find_package(LogRange CONFIG REQUIRED)`
  resolves the `LogRange::logrange` interface target and supplies the
  include directory and the C++17 requirement.
- Vendorable via `add_subdirectory`, without imposing this project's
  warning/test flags on the consumer.

**Constraints**

- C++17 only; the supported scope is `double` — no float or
  extended-precision contract is provided.
- Do not compile a translation unit that includes LogRange with
  `-ffast-math` or `/fp:fast`. The header rejects those modes unless
  `LOGRANGE_ALLOW_FAST_MATH` is defined, and using that opt-out voids the
  documented accumulator error contract.

**Provenance**

Extracted from the research repository
[`iouel/logrange`](https://github.com/iouel/logrange) (branch
`projectsummary`); see [NOTICE.md](../../NOTICE.md) for full provenance and
[research notes](../research.md) for the derivation of the error contract.
This release makes no performance or numerical claims beyond what is
documented in the [guarantees](../guarantees.md) page.
